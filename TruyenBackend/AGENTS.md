# Mộc backend rules

Scope: this directory and descendants. Read the project skill at `.agents/skills/moc-python-backend/SKILL.md` for shared conventions before implementation.

## Current state

Runtime now implements FastAPI, local PostgreSQL, Alembic migrations, explicit seed, account sessions and per-user progress. Read README.md for actual commands. PostgreSQL lives in the Docker volume; preserve it. Web and app consume auth/progress APIs and retain local offline reading.

## Architecture decisions

Use the reviewed FastAPI / Pydantic 2 / SQLAlchemy 2 async / asyncpg / Alembic direction, based on Python 3.12. Choose supported compatible versions at runtime setup. `/api/v1` is the API root; public/auth/reader are the implemented route groups. Add admin routes only for a requested feature.

Follow `main → routes → controllers → services → repositories → models`; schemas and shared constants/utilities support these layers. Controllers adapt HTTP; services implement use cases; repositories own queries. Read nested AGENTS.md in touched folders.

One settings object (`constants/config.py`), one SQLAlchemy Base (`constants/database.py`), one service/request transaction boundary. No database commits inside repositories/models and no duplicate registries. Do not perform migrations/imports at server import or startup.

Return typed `GenericResponse[T]` matching the selected wire contract in the skill; use real HTTP status codes and consistent handlers. Do not copy the source's ad-hoc JSONResponse success envelope.

Preserve legacy book/chapter identifiers, duplicate-number parts and zero-based content order from the existing readers. Metadata lists are bounded (default 50, max 100), exclude bodies, and sort deterministically. Verify object ownership and role gates; never trust a submitted user ID for personal data.

Do not log credentials, request/response bodies or raw authorization headers. No placeholder production signing key, access-token-as-refresh behavior, raw exception disclosure or wildcard credentialed CORS.

## Verification

After runtime setup, use its configured Ruff, pytest and dependency checks; test actual HTTP payloads, authorization failures and atomic rollback. PostgreSQL-specific behavior and Alembic upgrades need a disposable PostgreSQL instance. Mark unavailable checks as unverified. Full details in the skill's validation reference.

No rule grants permission to reset real data, create hosted resources, deploy or modify happyvow-api upstream. Respect subsequent user instructions about implementation scope.

## Source hygiene and Git

Keep C:/Truyen folder-only at the top level (including the .git directory). Git tracks all projects from that root; never create a nested repository. Keep secrets, input novels, generated bundles, dependencies and build output untracked. Docker configuration belongs only to TruyenBackend. Preserve the green/cream/night branding and guest offline reading. Update imports, scripts, tests and documentation together when moving files. Do not add one-off status probes or generated check reports to source; keep meaningful automated tests and required build guards. No hosted deployment or Git push is implied by a code change.

## Cultivation reference data

Client offline snapshots are generated by content preparation, not independently edited copies.
